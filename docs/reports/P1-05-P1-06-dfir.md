## 2. P1-06 — DFIR triyaj akışı

### 2.1 Araç: `examples/22_dfir_triage.ax`

Tek komut → tek JSON rapor:

| Bölüm | Kaynak |
|---|---|
| `processes` | `/proc/*/comm` (`forensics_list_processes`) |
| `network` | `/proc/net/tcp` LISTEN (`forensics_list_listening_ports`) |
| `integrity` | `/etc/passwd`, `/etc/shadow`, `/etc/hostname`, `/etc/ssh/sshd_config` SHA-256 |
| `log` | `AXIOM_DFIR_LOG` veya `/var/log/{auth.log,secure,apache2/access.log}` |
| `detections` | Sigma motoru (log tipi satırdan çıkarılır) |
| `risk` | En yüksek risk → `info/low/medium/high/critical` |

```json

  "version": "0.1.0",

  "network": {"listening_count": "2", "listening": [{"ip": "127.0.0.1", "port": "22"}]},
  "integrity": [{"path": "/etc/passwd", "sha256": "33a8...", "status": "hashed"}],

    {"rule_id": "SQL_INJECTION", "level": "Critical", "risk": "100"}]},
```

## 3. Bu turda bulunan 4 gerçek hata

DFIR aracını C ve LLVM'de çalıştırmak, parite ilkesinin neden zorunlu olduğunu
bir kez daha gösterdi: **C çalışıyordu, LLVM sessizce boş/yanlış üretiyordu.**

### 3.1 C: `str[]` use-after-free (bellek güvenliği)

```axiom
fn build() -> str[] {
    let raw = str_split(text, "\n")
    let mut out: str[] = []
    let t = str_trim(raw[i])      # sahipli geçici
    out = array_push(out, t)      # yalnız gösterici kopyalanıyordu
    return out                    # t kapsamdan çıkınca free → sarkan gösterici
}
```

| Önce (C) | Sonra (C) | LLVM |
|---|---|---|
| `;��W` (çöp) | `aa,bb,cc` | zaten doğruydu |

**Düzeltme:** `axiom/codegen_c.py` — `inferred_type == "str[]"` ise
`axiom_array_push_str` (elemanı sahiplenir/kopyalar) üretilir.

### 3.2 LLVM: string literal çift çözümleme

Kaynak `"\\\""` (ters bölü + tırnak) lexer'da `\"` oluyor; LLVM üreteci bunu
**tekrar** çözüp `"` yapıyordu.

| Önce | Sonra |
|---|---|
| `str_replace("a\"b", "\"", "\\\"")` → `a"b` | `a\"b` |

İki ayrı yerde kopyalanmış kaçış mantığı tek yardımcıya indirildi:
`_llvm_escape_bytes()`.

### 3.3 LLVM: `str_join` ABI uyumsuzluğu (segfault)

`ax_array_str` (24 bayt) **değerle** geçiliyordu; clang tarafı `byval(ptr)`
bekliyor → `SIGSEGV`. Projede aynı sınıf hata için `*_ptr` sarmalayıcı deseni
vardı (`simd_*_ptr`, `json_build_object_ptr`); `axiom_str_join_ptr` eklendi ve
`PTR_ABI_SYMBOLS`'a kaydedildi.

### 3.4 `file_read` procfs

`/proc/sys/kernel/hostname` gibi dosyalar `stat` boyutunda 0 görünür; eski kod
`fseek/ftell` ile 0 okuyup boş dönüyordu. Akış tabanlı yedek yol eklendi.
Sonuç: `host` artık gerçek makine adı.
